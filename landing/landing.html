01 Harvest now, decrypt later

The data you send today can be read tomorrow.

Attackers can record encrypted traffic now and decrypt it once a large quantum computer exists. Every company knows this. Almost none can say which systems break first, or when.

02 How it works

Scan, forecast, prove, migrate.

step 01

Scan

Reads live websites and source code in eight languages and exports a CycloneDX 1.6 cryptography bill of materials.

step 02

Forecast

Compares each algorithm's published cost in logical qubits and gates with IBM's roadmap, year by year.

step 03

Prove

Runs Shor's algorithm and Grover's search, built in Qiskit, on real IBM quantum computers, and steps through them gate by gate with our quantum-debugger library.

step 04

Migrate

Swaps in NIST's post-quantum standards, ML-KEM and ML-DSA, with a working hybrid handshake.

03 Real hardware

We ran the attacks on three IBM quantum computers.

Toy-sized keys, real machines: ibm_fez, ibm_kingston and ibm_marrakesh. Every pass rule was fixed in code before the runs, and two negative controls had to fail.

45 / 45validation tests passed on 3 machines
24 / 24strict Shor tests passed on every machine and placement
14 / 14strict tests passed on ibm_kingston, repeat run included
10 / 18strict Grover tests passed

Every run beat random noise. Grover failed some strict checks because it must keep quantum phases intact through about 140 two-qubit gates, and on ibm_marrakesh the qubits it ran on decided the result: 22% on one set, 64% on another. That gap is why a real attack needs fault-tolerant machines.

1,002 tests and a tool you can put in CI.
